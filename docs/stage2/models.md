# Модели машин и людей (glTF вместо процедурных)

Цель: постепенно заменить процедурные машины трафика/парковки и пешеходов на нормальные модели из бесплатных источников.
Замена — по видам: если для вида есть модель, она используется, иначе остаётся процедурная. Отключить всё glTF:
`?vehicles=proc`, `?people_view=proc`; взять только часть машин: `?vehicles=lada_largus,vaz2107`.

## 1. Машины

### Источники и лицензии
- Все модели и их лицензии — `game/CREDITS.md` и поля `license/author/url` в `game/public/assets/vehicles/vehicles.json`.
- Каталог кандидатов (Sketchfab и др., с uid, лицензией, полигонажем, рангом) — `assets/catalog/vehicles.json`.
- Sketchfab скачивает только с API-токеном: файл `~/.config/sketchfab/token` (токен пользователя, страница
  sketchfab.com → Settings → Password & API). Скрипт `assets/scripts/vehicles/fetch_sketchfab.py` читает токен оттуда
  (не печатает), берёт очередь `queue` из каталога и кладёт исходники в `assets/sources/sketchfab/<id>/` (+ meta.json с лицензией).

### Конвейер (`assets/scripts/vehicles/`)
1. Конфиг модели `configs/<id>.json`: `id, name, kind` (класс трафика: sedan/hatch/wagon/suv/taxi/police/gazelle/paz/liaz/trolleybus),
   `roles` (`traffic`, `parked`), `src` (путь к исходнику), `forward` (куда смотрит перёд в осях Blender после импорта:
   `+Y/-Y/+X/-X`), `dims` (реальные габариты и база), `scaleBy` (`length`|`wheelbase`), `budget` (треугольники LOD0 вместе
   с колёсами), `lod1Budget`, `materialRoles` (имя/regex материала → роль), `deleteObjects`/`deleteMaterials` (салон,
   двигатель…), `wheelsFromLooseParts`, `keepPaintTexture` (ливреи), `fixedPaint`, `paintVariants`, лицензия/автор/url.
2. `blender -b --python build_vehicle.py -- configs/<id>.json <tmp>`:
   импорт (glTF/GLB/FBX/OBJ/.blend) → применение трансформов → удаление лишнего → ориентация (перёд −Z glTF) →
   поиск колёс (по именам объектов/материалов или по геометрии) и кластеризация в 4+ колеса → масштаб до реальной
   длины/базы → начало координат на земле между осями → кузов одной сеткой → децимация до бюджета → колесо-шаблон
   (правое заднее) → роли материалов → **запекание всех материалов в один атлас** (Cycles DIFFUSE color, новая UV,
   лак запекается белым — цвет даёт инстанс) → экспорт LOD0 (`body` + `wheel`) →
   **LOD1**: выпуклая оболочка → равномерный воксельный ремеш → shrinkwrap к модели → децимация (~1.5k) → роли граней
   от ближайшей грани LOD0 → запекание LOD0 на LOD1 (selected-to-active, 256²) → `<id>.json` (габариты, колёса, база, колея).
3. `sh pack_vehicle.sh <tmp> <id>` — gltf-transform: dedup, prune, resize (1024 / 256), WebP, meshopt →
   `game/public/assets/vehicles/<id>/<id>.glb`, `<id>_lod1.glb`, `build.json`.
4. `node make_manifest.mjs` → `game/public/assets/vehicles/vehicles.json` (только собранные модели).
5. Проверка: `blender -b --python preview.py -- <glb> <png>` (Workbench-рендер 3/4), затем в игре.

Конвенция glb: +Y вверх, перёд −Z, метры; начало — на земле между осями. Материалы по ролям `paint, glass, headlight,
taillight, brakelight, indicator, beacon, sign, trim, chrome, tire, rim, interior, plate` — все с одной текстурой-атласом.

### Как добавить машину
1. Скачать исходник (Sketchfab: `python3 -I assets/scripts/vehicles/fetch_sketchfab.py <id>`; другое — вручную в
   `assets/sources/<сайт>/<id>/` вместе с лицензией).
2. Посмотреть структуру (`blender -b --python preview.py -- <src> /tmp/a.png` и список объектов/материалов),
   написать `configs/<id>.json` (скопировать похожий), указать `forward`, `dims`, роли непонятных материалов.
3. Собрать (`build_vehicle.py` → `pack_vehicle.sh` → `make_manifest.mjs`), проверить превью и в игре.
4. Дописать атрибуцию в `game/CREDITS.md`.

### Рантайм
- Процедурные машины (без glTF) — параметрический генератор `game/src/vehicles/procedural/`, см. [docs/stage3/procedural-cars.md](../stage3/procedural-cars.md).
- `game/src/traffic/gltf-models.ts`: `VehicleLibrary.load()` (манифест + glb, слияние примитивов в одну геометрию с
  атрибутами `position/normal/uv/color/aPart` — тот же контракт, что у процедурных моделей; aPart по имени материала),
  `GltfTrafficLayer` — на модель InstancedMesh ближний / ближний с тенью / LOD1 + InstancedMesh колёс (вращение и руление
  по экземпляру, левые колёса — шаблон, повёрнутый на π). Материал — тот же `vehicleMaterial` (окраска по instanceColor
  только для лака, фары/стопы/поворотники/маячки по aLamp) + карта атласа.
- Вариант модели выбирается по id машины (хэш, с весом `weight`); модель сдвигается вдоль оси так, чтобы её задняя ось
  совпала с задней осью процедурной модели вида (кинематика симуляции ведёт машину по задней оси).
- Хук в `render.ts`: если `renderer.gltf.has(kind)` — машину рисует слой, иначе процедурная. Подключение — `main.ts`.
- Парковка: `game/src/world/parked-gltf.ts` строит виды пропсов `car_<id>` (LOD0: кузов + колёса одной геометрией,
  LOD1) и процедурные `car_p_sedan/hatch/wagon/suv` (кузова трафика + колёса); `Props.addParkedCarModels()` регистрирует
  их до подгрузки тайлов. Выбор вида для `parked_car` — взвешенный по хэшу `seed`: каждая glTF-модель ≈12% × `parkedWeight`
  (все glTF вместе ≤ 85%), остаток — процедурные; цвет — палитра `carColor(seed)` (кроме моделей с ливреей в текстуре).
  Постановка — как у процедурных: высота и наклон по поверхности под 4 колёсами (дорога +0.05, тротуар +0.15, площадка +0.03);
  начало координат модели — низ колёс.
- Толкаемые машины парковки (`props.ts`, класс `parked_car` в `breakables.ts`): за ~1.5 шага физики до контакта (игрок или
  уже сдвинутая машина) статический коллайдер заменяется динамическим телом Rapier — коробка по габариту, 1200 кг, центр
  масс ниже на 0.3 м, трение 0.6, демпфирование 0.35/0.9; удар считает сам Rapier (без «стены»). Остановилась (сон/скорость ≈ 0),
  отъехала дальше 220 м или превышен лимит 20 динамических — снова инстанс + статический коллайдер на новом месте; новое
  положение хранится до конца сессии (`movedCars`, ключ — тайл + исходная точка) и применяется при перезагрузке тайла.
  Хук `props.onParkedCarHit(x, y, z)` — для звука сигнализации (пока не подключён).
  Проверка: таран ряда на 40 км/ч — машина игрока теряет скорость до ~17 км/ч в первый удар и толкает 2 машины цепочкой.

### Рантайм (`game/src/people/gltf-people-view.ts`, реализует `PeopleView` и `RagdollSkin`)
- `People` (index.ts) создаёт `GltfPeopleView`; пока ассеты грузятся или при ошибке — внутренний `ProceduralPeopleView`;
  `?people_view=proc` — только процедурные.
- GPU-скиннинг инстансов: при загрузке все клипы запекаются на скелете каждого персонажа в half-float DataTexture матриц
  (3 текселя на кость, строка = кадр 30 fps); на персонажа и LOD — один InstancedMesh; шейдер (`onBeforeCompile`
  MeshStandardMaterial + такой же MeshDepthMaterial для теней) читает до 4 костей `texelFetch`, интерполирует кадры и
  смешивает два клипа (A/B с весом).
- **Походка по скорости.** Скорость по земле вид считает сам — по смещению матрицы агента между кадрами (ключ —
  индекс агента, сглаживание ~0.1 с); фаза шага накапливается в виде: Δцикла = v·dt / длина цикла (длина цикла — по проходу
  таза в mocap × длина ноги персонажа × масштаб). Ходьба и бег смешиваются по скорости (с фазой, общей для обоих клипов);
  при остановке темп падает до 0 и клип плавно переходит в idle (0.1–0.45 м/с), при старте — обратно. Проскальзывание
  опорной стопы (лодыжка, на отрезке опоры): 0.8 м/с — в среднем 3.8 см (макс. 7.6), 1.3 м/с — 3.6 (4.0), 1.8 м/с — 3.5
  (4.1), 3.0 м/с — 3.2 (4.8); это в основном естественный перекат пятка→носок. Фаза агента (`look.anim.x`) больше не
  используется. Переходы между позами — 0.25 с, подъём после падения/рэгдолла — 0.45 с.
- **Цвета.** У каждого человека 8 цветов (верх, низ, обувь, волосы, шапка, внутренний верх, шарф, перчатки), выбираются
  стабильно по хешу внешности из палитр осеннего города (куртки: тёмно-синий, оливковый, бежевый, серый, бордовый,
  горчичный, светлый деним, чёрный, коричневый + немного ярких спортивных; у женщин — кэмел, сливовый, пыльно-розовый,
  кремовый; у детей — яркие; у пожилых — приглушённые; обувь в основном чёрная/коричневая/серая, ~10% белых кроссовок),
  с разбросом яркости ±12%. Цвета упакованы в атрибуты инстанса как 0xRRGGBB (2 × vec4). Дальние процедурные люди
  рисуются в тех же цветах.
- **Сезон.** `GltfPeopleView.setWinter(f: number)` (0 — осень, 1 — зима, дробное — доля «зимних» людей),
  `setSeason('autumn' | 'winter')`, `winterAmount`; то же на обёртке: `people.setWinter(f)` / `people.setSeason(s)`.
  Зимой выбираются зимние варианты персонажей (пальто/куртки, шапки, шарфы, перчатки) и тёмная палитра (дети — яркие);
  выбор стабилен по хешу, при смене значения все переодеваются в следующем кадре.
- Персонаж выбирается стабильным хешем внешности внутри пула по типу тела (6-й аргумент `push(..., body)`) и сезону; рост
  нормируется к 1.75 × scale агента.
- Позы: Walk → локомоция по скорости (idle/walk/run); Sit/Talk/Phone/Angry/Fallen → свои клипы; Angry на ходу → walk+angry;
  Dodge — разовый (если при этом идёт шаг — ходьба).
- LOD: < 70 м — LOD0 с тенями (до 160 на персонажа), до 170 м — LOD1 (до 320), дальше/переполнение — процедурные.
- Рэгдоллы и подъём — см. ниже.
- Отладка: `view.debugWatch(id)` + `view.debugJoint(id, 'LeftFoot')` — мировая позиция сустава (тот же скиннинг на CPU).
- Правки вне нового файла: в `people-system.ts` — передача `bodyA[i]` в `push` и условие `!view.holdDown?.(i)` в выходе из
  «лежит»; необязательные `body?` в `PeopleView.push` и `holdDown?` в `PeopleView`; подключение, `setWinter/setSeason`,
  `heightAt` и `?ragdoll_debug=1` в `index.ts`; `ragdoll.ts` (ниже).

### Рэгдоллы и подъём (`game/src/people/ragdoll.ts` + `gltf-people-view.ts`)
Было: шаровые шарниры без пределов; пределы локтей/коленей задавались через `JointData.limits`, которые в этой версии
Rapier JS молча игнорируются (проверено: работают только `setLimits` после создания) — локти и колени гнулись в обе стороны;
размеры тел — одни на всех; части одного рэгдолла не сталкивались; при переходе «рэгдолл -> анимация» персонаж на кадр
вставал в позу «лежит» процедурного вида (раскинутая Т-образная поза, повёрнутая матрицей) и поднимался поворотом матрицы.

Стало:
- **Тела по костям персонажа.** glTF-вид отдаёт суставы позы «стоит» (1-й кадр idle) — `RagdollSkin.shape(agent)`; таз,
  торс, голова, плечи, предплечья (+кисть), бёдра, голени (+стопа) строятся по ним (капсулы вдоль сегментов, тела в покое
  ориентированы по yaw человека, коллайдеры повёрнуты внутри). Без скина — эталон 1.75 м. Массы: 73 кг × (рост/1.75)³
  по долям (таз 16%, торс 30%, голова 7%, плечо 3.5%, предплечье 2.7%, бедро 11%, голень 6.2%), инерция — от формы.
  Тела создаются при ударе и удаляются, когда человек улёгся (пул — 8 слотов).
- **Шарниры.** Локти — revolute 0…140° (сгиб вперёд), колени — revolute −140…0° (назад), `setLimits`. Позвоночник,
  шея, плечи, бёдра — сферические; у них в JS-API Rapier нет пределов, поэтому конус и скручивание эмулируются перед каждым
  шагом физики (`physics.onPreStep`): относительный поворот раскладывается на swing (отклонение оси кости) и twist (вокруг
  неё); выход за предел гасит относительную угловую скорость «наружу» (распределение по массам) и добивает к границе
  (β = 0.25). Пределы (конус/скручивание): позвоночник 25°/±20°, шея 40°/±50°, плечо 95°/±60°, бедро 70°/±35°.
  Демпфирование: тела — линейное 0.12, угловое 1.2; шарниры — 4% относительного вращения за шаг.
- **Коллизии.** Части одного рэгдолла сталкиваются, кроме пар с шарниром (`contactsEnabled = false`); руки с ногами — без
  сил (solver groups: в позе «стоит» кисть касается бедра). Membership — бит 5, как раньше (лучи подвески и выстрелы его
  исключают).
- **Отладка.** `?ragdoll_debug=1` (или `pool.debug = true`) — тела каркасом поверх персонажа: совпадают с ним во время
  полёта (кости привязаны к телам: M = W_тела(t)·W_тела(0)⁻¹·L·S_idle).
- **Подъём.** Когда рэгдолл улёгся, вид запоминает его позу (матрицы костей в мире), по торсу определяет «лицом вверх/вниз»
  и запускает клип getup_back / getup_front: 1-й кадр клипа ставится тазом в таз рэгдолла и головой в ту же сторону,
  за 0.6 с поза рэгдолла перетекает в клип, дальше играет клип. Точку и направление, где человек встанет (конец клипа),
  вид записывает в результат рэгдолла — people-system ставит туда агента и, пока идёт клип, держит его в «лежит»
  (`holdDown`), потом штатные GetUp (0.8 с) и «сердится». Передача обычному виду — с переходом 0.25 с из последнего
  кадра клипа. Позы покоя/Т-позы не видно ни в один кадр.
- Процедурный вид (`?people_view=proc`) по-прежнему: коробки рэгдолла -> поза «лежит» процедурного человека с подъёмом
  поворотом матрицы (смена позы при отпускании остаётся). Дети в рэгдолл не попадают (решает people-system) — у них «кувырок».
- Цена: проход пределов — 6 шарниров на активный рэгдолл за шаг физики; подъём — распаковка 23 костей из half-float на
  кадр на поднимающегося; создание тел — только при ударе. На кадр это незаметно.

### Известные ограничения
- Нет CC0-пуховиков, худи, ушанок, платков; у женщин в юбках голые голени; узор некоторых курток при светлом тоне пятнистый.
- Мелкие ошибки покраски на стыке верха и низа костюмов. Клипы подъёма CMU (139_18, 140_01) у этих актёров заканчиваются с наклонённым корпусом — выпрямление добирает переход в «сердится».
- Ретаргет без IK стоп; лёгкий дрейф курса в idle; дети в рэгдолле кувыркаются по-старому.
- Draw calls растут с числом разных персонажей в кадре (до 2 на персонажа + тени LOD0).

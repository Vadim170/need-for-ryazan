# Реестр домов: реальные атрибуты зданий (этап 2)

Цель: этажность, год, материал стен, тип крыши, подъезды для многоквартирных домов из публичных реестров ЖКХ, с привязкой к зданиям OSM по адресу. Потребитель: `pipeline/world/buildings.py` (типовые серии, высота) и «стритлайф» (подъезды).

## Как работает

1. `pipeline/fetch_registry.py` (`uv run python fetch_registry.py [domreestr|mkdbase|all] [--limit N]`)
   - Список улиц Рязани: domreestr — из их sitemap (307 улиц; разовый обход 27 файлов sitemap занимает ~20 мин, результат кэшируется), mkdbase — страницы списка улиц города.
   - Страницы улиц domreestr показывают по 10 домов; остальное берётся через AJAX-пагинацию самого сайта (POST `tmpl=module&mid&key&mp`).
   - Страницы отдельных домов качаются только для адресов, которые есть в OSM bbox (пара «улица + дом» после нормализации). mkdbase дополнительно ограничен адресами, найденными в domreestr (иначе 4.7k страниц частных домов без данных).
   - Вежливость: User-Agent с контактом, глобальный лимит ~1.4 запроса/с (3 потока), ретраи с backoff, кэш каждой страницы в `data/raw/registry/<source>/` (повторный запуск ничего не перекачивает). Полный холодный прогон — порядка 1–1.5 ч.
   - Выход: `data/raw/registry/domreestr.json`, `mkdbase.json`.
2. `pipeline/match_registry.py` (`uv run python match_registry.py`) -> `data/processed/building_registry.json` и `building_registry_stats.json`.
   - Нормализация (`pipeline/registry_common.py`): регистр, ё/е, убирается тип улицы (улица/ул./пр-кт/пер./пр-д/шоссе/...), порядок слов не важен («1-й Новый проезд» = «Новый 1-й проезд»), латинские двойники букв, «д. 95, к. 1» = «95/1» = «95 к1», «10 к А» = «10а», строения `с`, литеры.
   - OSM `addr:housenumber` вида `12;14` разбивается на несколько адресов; для здания с несколькими адресами значения агрегируются (levels = max, levels_min = min, подъезды суммируются).
   - Несколько контуров OSM на один адрес: берётся ближайший к координате реестра (порог 50 м до контура); без координат — самый большой жилой контур.
   - Источники склеиваются по (улица, дом): этаж/год/подъезды/координаты — приоритет domreestr, материал/крыша — mkdbase.

Только контуры-ways; здания-relations (multipolygon) в сопоставлении не участвуют. Файл `ryazan.osm` содержит данные и вне bbox (зеркала Overpass отдавали лишнее) — `registry_common.load_osm_buildings` фильтрует по BBOX сам.

## Формат `building_registry.json`

`{ "<osm_way_id>": {levels, levels_min?, year?, series?, series_raw?, wall_material?, roof_type?, roof_material?, entrances?, lifts?, n_addresses, source_url} }`

- `levels` — наибольшая этажность; `levels_min` — только если меньше (секции разной высоты, «5–9»).
- `wall_material`: Кирпич / Панельные / Блочные / Деревянные / Смешанные / Монолитные / Иные.
- `roof_type` — форма (Плоская / Скатная / Двускатная / Вальмовая), `roof_material` — кровля (Шиферная, Рулонная, Мягкая, профлист, ...). Есть только у ~16–22% записей.
- `series` — только осмысленные значения (типовая серия 121, 83, 1-511, П-3, 1-447, ...); мусор («Сведения отсутствуют», «кирпичный») отфильтрован, оригинал в `series_raw`.
- Поля могут отсутствовать, если в реестре данных нет.

## Покрытие (bbox: 8290 зданий OSM, 1915 `building=apartments`)

- Записей реестра с данными: 1725; сопоставлено со зданиями OSM: **1717** (20.7% всех зданий).
- Многоквартирных (`apartments`) сопоставлено **1457 из 1915 = 76.1%**.
- Этажность: у 20.6% зданий OSM уже есть `building:levels`; реестр добавляет её ещё **969 зданиям (+11.7% от всех)** -> итого ~32.3% зданий с этажностью.
- Поля: levels 1710, год 1565, подъезды 1647, лифты 1540, материал стен 1559, форма крыши 270, кровля 386, серия 204 (883 с «сырым» значением).
- Контроль по координатам: 1526 однозначных + 62 выбранных среди нескольких контуров; 8 отброшено (>50 м от контура).
- **Согласие с OSM `building:levels`** там, где есть оба (738 зданий): точное совпадение **90.0%**, в пределах ±1 этаж 96.9%. Расхождения: по большей части реестр на 1 этаж больше/меньше (мансарда, цоколь), единичные большие — вероятно, ошибки в OSM или составные здания.

Не покрыто: частный сектор (не в реестрах МКД), нежилые здания, МКД, которых нет у обоих агрегаторов или чей адрес в OSM записан нестандартно.

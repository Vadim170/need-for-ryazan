# Этап 1: пайплайн мира («серый бокс»)

Скрипт `pipeline/build_world.py` собирает из сырых данных каталог `game/public/world/` в формате [docs/world-format.md](../world-format.md). Сборка занимает около 17 секунд на M-серии Mac.

## Запуск

```bash
cd pipeline
uv sync                          # numpy, shapely, rasterio, scipy, trimesh, mapbox-earcut, eclipse-sumo
uv run python build_world.py     # сборка мира, в конце печатает сводку
uv run python verify_world.py    # проверки + превью и профили в data/processed/

# тестовая сборка, не трогая game/public/world (промежуточные файлы — в <out>_work):
uv run python build_world.py --out ../data/processed/world_test
uv run python verify_world.py --world ../data/processed/world_test [--bridges-only]
```

Входные данные (уже скачаны на этапе 0): `data/raw/osm/ryazan.osm` и `data/raw/dem/fabdem/fabdem_crop.tif`.
Промежуточные файлы лежат в `data/processed/sumo/`: отфильтрованный OSM, typemap, `net.xml` и `h_stages.npy` (рельеф до и после обработки, нужен для профиля).

Код:
- `pipeline/build_world.py`: оркестрация, ленты дорог, мосты, тайлы, граф, спавны.
- `pipeline/world/osm.py`: разбор OSM, здания, вода, автодороги, запись отфильтрованного OSM для netconvert.
- `pipeline/world/sumo_net.py`: typemap с ширинами полос, запуск netconvert, разбор `net.xml`.
- `pipeline/world/terrain.py`: FABDEM → сетка, вода, вжатие дорог, рельеф под мостами.
- `pipeline/world/bridges.py`: профиль настила, насыпи у опор, выравнивание парных мостов, поверхность ленты, толщина плиты, дороги под мостами.
- `pipeline/world/roads.py`: сборка двусторонних дорог, высоты перекрёстков, продольные профили, мосты и путепроводы.
- `pipeline/world/buildings.py`: тип, высота, экструзия.
- `pipeline/world/gltf.py`: свой минимальный писатель GLB (именованные ноды, примитивы по материалам, `extras`).
- `pipeline/world/grid.py`: сетка высот; выборка высоты по тем же треугольникам, что у коллайдера.
- `pipeline/verify_world.py`: проверки результата.

## Почему SUMO netconvert

Колесо `eclipse-sumo` 1.28 штатно работает на Apple Silicon (arm64, Python 3.12) внутри venv, без brew. netconvert обрабатывает весь bbox за 2–3 секунды. Он даёт то, что вручную через буферы shapely получается плохо:
- раскладку полос по направлениям из `lanes`, `lanes:forward`/`backward` и `oneway`, с разумными значениями по умолчанию;
- нормальные многоугольники перекрёстков (включая объединение близких узлов `--junctions.join`), развязки и кольца;
- граф, пригодный для будущего трафика: `net.xml` с соединениями полос и светофорами (`--tls.guess-signals`) сохраняется.

Как настроено:
- Проекция задана той же tmerc, что `WORLD_CRS` (`--proj … --offset.disable-normalization`), поэтому координаты `net.xml` уже мировые.
- Ширины полос задаёт свой typemap: primary/secondary 3.5 м, tertiary 3.25, residential/unclassified 3.0, service/living_street 2.75. OSM-теги `width` игнорируются (`--ignore-widths`), потому что в данных встречаются полосы по 2 м.
- Перед netconvert OSM фильтруется: остаются только автодороги, пути режутся по границе мира. Новый id куска = `osm_id*100 + k`, так что `osmId` в графе восстанавливается.

## Алгоритм

1. **Границы.** bbox этапа 0 переводится в мировую СК и расширяется до кратных 250 м: x ∈ [−3250, 4000], север y ∈ [−4250, 3250], то есть three.z ∈ [−3250, 4250]. Получается 29×30 = 870 тайлов.
2. **Рельеф.** FABDEM передискретизируется бикубически в узлы сетки 5 м (1451×1501) и сглаживается гауссом σ = 17.5 м (рекомендация аудита рельефа).
3. **Вода.** Берутся полигоны OSM (`natural=water`, `waterway=riverbank`, `landuse=reservoir/basin`), всего 62. Уровень воды = 10-й перцентиль сырого FABDEM внутри полигона; у Оки получается ровно 90.0 м. Дно опускается на 1.5 м ниже уровня. Берег на 30 м вокруг ограничивается сверху значением `уровень + 0.3 + 0.4·d`, чтобы не было вертикальной стенки. Водная поверхность выводится плоскими полигонами на уровне воды.
4. **Дороги.** Направленные рёбра SUMO склеиваются в неориентированные дороги: пара `X` / `-X`, иначе дорога односторонняя. Ось двусторонней дороги — линия между направлениями, односторонней — середина проезжей части.
5. **Высоты перекрёстков.** Это среднее сглаженного рельефа по площадке перекрёстка. Узлы, к которым примыкают только мосты (середина моста), интерполируются гармонически по мостам. Затем итеративно ограничивается уклон между соседними перекрёстками: primary/secondary 8%, tertiary 10%, residential/unclassified 12%, service 14%, мосты 6%.
6. **Продольный профиль** каждой наземной дороги (шаг 2 м): рельеф по оси, гаусс вдоль оси σ = 12 м, линейная поправка, чтобы концы совпали с высотами перекрёстков, затем прямой и обратный проходы с ограничением уклона.
7. **Мосты** (`bridge=*`, 30 путей OSM; код в `world/bridges.py`).
   - Настил — верхняя огибающая трёх кривых: линия между высотами опор; «шатёр» над наземными дорогами под мостом (13 пересечений, `дорога + 5.5 м + 0.5 м` запаса на скругление, склоны 6%); сглаженный (σ 15 м) максимум рельефа под осью и краями настила. Последнее нужно потому, что FABDEM содержит реальные насыпи, например насыпь Северной окружной в пойме, и настил не должен в неё врезаться.
   - Параллельные мосты (две проезжие части одного путепровода, оси ближе 20 м) выравниваются по высоте.
   - Профиль скругляется (гаусс σ 8 м), концы возвращаются на высоты опор, уклон ограничивается.
   - **Насыпь.** Насыпью считается участок, где настил ниже 1 м над землёй, а также последние ≤12 м у наземной опоры (но не ближе 12 м к дороге снизу). Насыпь вжимается в рельеф как обычная дорога. Под пролётами рельеф опускается до `настил − 1.5 м`.
   - **Стык с опорой.** На ≤12 м у наземной опоры поверхность ленты плавно переходит от настила к рельефу +0.05 м, поэтому ступеньки на стыке нет. Плита-коллайдер на этих метрах сходит с 0.8 до 0.05 м.
   - **Висячие узлы.** Узел, где сходятся только мосты, остаётся «висячим» (площадка-коллайдер на высоте узла), если он над пролётом или рядом с дорогой снизу. Иначе он считается наземным.
   - **Дороги снизу.** Если габарит всё равно не набран, дорога снизу опускается выемкой с уклоном её класса. Задетые перекрёстки получают верхнюю границу высоты, и шаги 5–7 повторяются (до 4 итераций). После сглаживания вжатия ядро таких дорог дополнительно прижимается к их профилю.
8. **Вжатие в рельеф.** Узлы сетки рядом с осями получают вес: 1 в пределах полуширины + 1 м, затем smoothstep до 0 на расстоянии +8 м (обочина). Площадки перекрёстков растеризуются с весом 1 на своей высоте с тем же спадом. При пересечении коридоров побеждает больший вес. Итог: `h = h·(1−w) + профиль·w`. Приращение от вжатия дополнительно сглаживается гауссом σ = 5 м, чтобы убрать ступеньки между соседними площадками. Под настилом мостов рельеф опускается до `настил − 1.5 м` с плавным выходом к опорам. Наземные дороги под мостом при этом не трогаются.
9. **Тоннели** (22 пути, 0.34 км, в основном короткие проезды под домами) в v1 игнорируются: дорога идёт по поверхности рельефа.
10. **Меши дорог.** Для каждого направленного ребра SUMO строится лента от правой кромки полосы 0 до левой кромки крайней полосы, с вершинами не реже 4 м. Высота каждой вершины = рельеф (по треугольникам коллайдера) + 0.05 м, на мостах — профиль настила. Лента режется по тайлам по середине сегмента, без дублирования. Площадки перекрёстков триангулируются earcut на +0.06 м. Мосты дополнительно получают плиту 0.8 м (нода `bridges`) и замкнутый коллайдер (нода `bridge_colliders`).
11. **Здания** (8361 шт.). Это пути и мультиполигоны `building=*`; пропускаются `roof`, `carport`, `entrance`, `ruins` и подобные. Тип:
    - apartments: apartments, residential, dormitory, hotel;
    - house: house, detached, terrace…;
    - garage: garages, garage, shed…;
    - commercial: commercial, retail, office, supermarket;
    - всё остальное (включая `yes`) — other.

    Высота берётся по цепочке: `height` → `max(building:levels)·3 + 1` → умолчание (apartments 5 этажей = 16 м, house и commercial 2 этажа = 7 м, garage 3 м, other 7 м). Основание = минимум рельефа под контуром, так что на склоне дом утоплен в верхнюю часть склона. Здание попадает в тайл по `representative_point`. Рендер-меш строится по контуру, упрощённому до 0.2 м, коллайдер — по контуру, упрощённому до 1 м.
12. **Граф** (`roads/graph.json`). Узлы — перекрёстки SUMO, рёбра — неориентированные дороги с полосами по направлениям, точки оси шагом ~10 м с высотой поверхности.
13. **Спавны.** Всего 50 точек на primary/secondary/tertiary (без съездов, мостов и тоннелей): в середине правой полосы, `heading` вдоль полосы. Две точки фиксированы: «площадь Победы» (ближайшая primary/secondary полоса к 54.6293, 39.7116) и «пост ДПС» (54.6378, 39.7814). Остальные 48 расставлены равномерно по карте выборкой самой удалённой точки.

## Проверка (`verify_world.py`)

- **GLB читаются trimesh.** Набор нод соответствует контракту. `extras.collider = true` стоит на `building_colliders` и `bridge_colliders` (проверено чтением JSON-чанка).
- **Высоты рельефа (v1).** Вершины `terrain` совпадали с heightmap (максимальная ошибка 0 / 1e−10 м). С v1.1 ноды нет.
- **Дороги над рельефом.** 100% вершин наземных дорог стоят ровно на +0.05 м над heightmap. В 20 000 случайных точках внутри треугольников дорог на тайл рельеф пробивает дорогу не глубже 0.008 м: таких точек 0.045%, и это один тайл у развязки из 16 проверенных.
- **Мосты (v1.1, все 30 рёбер).** `verify_world.py` печатает по каждому мосту ступеньку на обоих концах, рельеф сбоку от настила и превышение над рельефом, а также габарит и уклон для каждой дороги под мостом. Боковые профили шести мостов с подходами — в `data/processed/bridge_profiles.png`.

  | Макс. ступенька настил / примыкание на конце | 0.48 м | 0.005 м |
  | Макс. рельеф выше настила сбоку (полуширина + 1 м) | 3.9 м | 1.6 м |

## Известные ограничения v1

- **Рельеф.** Точность рельефа ±3 м (FABDEM 30 м). Лыбедский овраг почти не виден, ручных оверрайдов склонов (Кремль, Трубеж) пока нет.
- **Тоннели и проезды под домами** игнорируются. Коллайдер дома, через который в OSM идёт `tunnel=building_passage`, перекрывает проезд.
- **Путепроводы.** Подъём на путепровод делается только на участке, помеченном `bridge`. Насыпи въездов, не помеченные как мост, сами не поднимаются; если они есть в FABDEM, настил идёт по ним. Если моста не хватает для габарита, нижняя дорога опускается выемкой (12 правок, уклон до 13% на unclassified и service).
- **Развязка Северной окружной** (~1250, −290). Две проезжие части расходятся на разных высотах: между ними склон до 1.6 м на ~6 м, на подходе к одному из мостов уклон 13.8% на ~9 м (плавно, без ступеньки). Короткий мост-огрызок 1 м (osm 882943213) у висячего узла даёт перепад 0.24 м на 1 м.
- **Пересечения коридоров.** Параллельные близкие дороги разной высоты и съезды service на крутых склонах дают местами уклон до ~16% (только service и residential).
- **Мосты.** Нет ограждений и опор. Плита моста — отдельный коллайдер: игре нужна нода `bridge_colliders`, иначе на мосту машина провалится на рельеф.
- **Чего пока нет.** Тротуаров (`sidewalks`), разметки и бордюров нет. Ленты двусторонней дороги разделены по направлениям (u = 1 у оси), поэтому разметку игра рисует по u.
- **Перекрёстки.** Площадки сделаны плоскими на высоте узла. На больших площадях на склоне (их немного) это заметная «полка».
- **Дороги у края мира** обрезаны в 3 м от границы.
- **Здания.** `building:part`, крыши, `min_height` не учитываются. 79% зданий имеют высоту по умолчанию. Основание дома — минимум рельефа под ним.
- **Рельеф.** С v1.1 рельеф в тайлы не пишется: игра строит меш и коллайдер из heightmap (минус ~80 МБ).
- **Источники.** Лицензия FABDEM некоммерческая (см. аудит рельефа).

## Изменения контракта

Все изменения обратно совместимы и описаны в [world-format.md](../world-format.md):
- Новые ноды `bridges` (визуал) и `bridge_colliders` (`extras.collider`). Правило: любая нода с `extras.collider = true` — коллайдер.
- В `roads` второй материал `road_junction` (UV = мировые метры). Ленты по направлениям: u = 0 у правой кромки, u = 1 у оси.
- Коллайдеры зданий не обязательно выпуклые: упрощённые призмы для trimesh.
- Абсолютные индексы тайлов `floor(x/250)`, `floor(z/250)` (бывают отрицательные). Зафиксирована диагональ триангуляции ячейки. Пустые ноды не пишутся.
- В graph.json добавлено поле `bridge`; `points` идут от границы площадки до границы площадки. У спавнов есть необязательное поле `name`.

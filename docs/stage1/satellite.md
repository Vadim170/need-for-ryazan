# Аэрофотосъёмка: базовый слой (stage 1)

Подложка для работы над перекрёстками, разметкой и дворами. Только для личного использования (данные Яндекса).

## Источники

| Источник | URL | Проекция тайлов | Zoom | Тайлов | Объём тайлов |
|---|---|---|---|---|---|
| Яндекс | `https://core-sat.maps.yandex.net/tiles?l=sat&x={x}&y={y}&z={z}&lang=ru_RU` | **эллипсоидальный Меркатор EPSG:3395** | z18 весь bbox+200 м; z19 ядро | 7482 + 5304 | ~396 МБ |
| Esri World Imagery | `.../World_Imagery/MapServer/tile/{z}/{y}/{x}` | Web Mercator EPSG:3857 | z18 весь bbox+200 м | 7568 | ~100 МБ (после удаления z19) |

- Тайловая сетка Яндекса: квадрат ±20037508.34 м в EPSG:3395 (y считается сверху вниз). Если взять формулы Web Mercator, получится сдвиг по y в сотни метров. В `fetch_satellite.py` для Яндекса используется `pyproj` EPSG:3395.
- Ядро z19 (`CORE_BBOX` в `fetch_satellite.py`): lat 54.615..54.642, lon 39.730..39.770 (+200 м): Кремль, Соборная, Первомайский, Театральная.
- **Esri z19 в Рязани недоступен**: сервер отдаёт заглушки «Map data not yet available» (серые плитки). Они удалены, Esri скачивается только на z18.
- Разрешение на нашей широте: z18 ≈ 0.35 м/px по земле, z19 ≈ 0.17 м/px. Поэтому ортофото 0.5 м/px — это даунсэмплинг z18, а ядро 0.25 м/px — даунсэмплинг z19.
- Скачивание: User-Agent, ~8 req/с на источник, пул потоков, 5 повторов, resume (существующие тайлы пропускаются). Раскладка: `data/raw/satellite/<source>/z{z}/{x}/{y}.jpg`.

## Ортофото (data/processed/ortho)

Все в WORLD_CRS (локальная tmerc, метры, начало — Кремль), RGB, COG с JPEG (q90) и овервью, вне покрытия чёрный.

| Файл | Размер px | Разрешение | Объём |
|---|---|---|---|
| `yandex_0.5m.tif` | 15022×15274 | 0.5 м | 109 МБ |
| `yandex_2m.tif` | 3755×3818 | 2 м | 7 МБ |
| `yandex_core_0.25m.tif` (z19, ядро) | 11943×13624 | 0.25 м | 74 МБ |
| `esri_0.5m.tif` | 15022×15274 | 0.5 м | 81 МБ |
| `esri_2m.tif` | 3755×3818 | 2 м | 7 МБ |

Охват 0.5 м: x −3406…4104, y −4240…3397 (м). Ядро: x −1467…1519, y −2571…835.

## Проверка привязки

`verify_ortho.py` рисует кропы 400×400 м с осями автодорог OSM (красные): `check_<src>_{pobedy,kremlin,teatralnaya,dps}.png`, плюс увеличенный `check_yandex_core_zoom_teatralnaya.png` (z19, 180×180 м).

Оценка по визуальной проверке (оси OSM относительно проезжей части; автоматическая оценка сдвига по тёмности асфальта в скрипте шумная, ей доверять нельзя):

| Источник | Ошибка привязки | Замечания |
|---|---|---|
| Яндекс | ≈1–3 м, систематического сдвига нет (проекция 3395 учтена верно) | съёмка почти в надир, ясный летний день, короткие тени, видны машины, пешеходные переходы, стрелки, бордюры |
| Esri | ≈2–5 м | съёмка другой даты (позднее лето/осень, длинные тени деревьев), сильнее завал зданий (off-nadir), заметно мягче/размытее |

## Качество для разметки

Яндекс заметно лучше: чётче, меньше завал зданий, видны зебры, стрелки, стоп-линии на крупных узлах (ДПС, Победы). Продольная разметка на узких улицах различима плохо — слишком много машин и теней; z19-ядро даёт чуть более резкую картинку, но это скорее апсэмплинг z18, реальной новой детализации немного. Esri подходит только как сравнение/запасной вариант. Водяной знак «Yandex» мелко присутствует на тайлах.

## Как перезапустить

```
cd pipeline
uv run python fetch_satellite.py [--count-only] [--sources yandex esri] [--zooms 18 19]
uv run python build_ortho.py [--sources yandex esri] [--skip-core]
uv run python verify_ortho.py
```

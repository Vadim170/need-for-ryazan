# Этап 3: покров по спутнику — заросли, луга, огороды

Цель — чтобы пустые места мира были похожи на настоящую Рязань, а не только «дома и газоны»: заросли клёна
ясенелистного по оврагам, вдоль железной дороги и за гаражами, некошеные луга и поля в пойме, огороды частного
сектора, вытоптанные пустыри, песок пляжей, щебень промзон. Источник — спутниковые снимки; OSM даёт только слабые
подсказки. Формат файлов для игры — раздел «Покров со спутника» в [world-format.md](../world-format.md).

## Запуск

```bash
cd pipeline
uv run python build_landcover.py              # всё: context → train → predict → post → export → validate → crops (~30 мин)
uv run python build_landcover.py post export  # только чистка и экспорт (~1 мин), если модель и вероятности уже есть
uv run python build_world.py                  # мир: деревья по кронам, заросли (хук в world/props.py)
```

Шаги по отдельности: `context` (слои OSM и рельефа 1 м, кэш `data/processed/landcover/context.npz`), `train`
(выборка + LightGBM → `model.txt`), `predict` (вероятности по чанкам 1 км → `proba.npy`, uint8), `post` (чистка →
`lc_1m.tif`), `export` (игра + точки деревьев/зарослей), `validate` (точность), `crops` (картинки проверки),
`sheets` / `trainsheets` (листы точек для ручной разметки). Зависимости в venv пайплайна: `lightgbm`, `scikit-learn`.

Код: `pipeline/landcover/` — `classes.py` (классы, сетка), `context.py` (OSM → битовые слои), `features.py`
(признаки), `model.py` (метки, обучение, предсказание), `post.py` (чистка), `export.py`, `viz.py`;
`pipeline/world/landcover_veg.py` — деревья и заросли в мире. Игра: `world/landcover.ts`, `materials.ts` (рельеф),
`grass.ts`, `trees.ts`, `props.ts`, `breakables.ts`.

| 3 | `thicket` | заросли: клён ясенелистный, ивняк, молодняк — плотная «рваная» масса средней высоты |
| 4 | `meadow` | высокая некошеная трава, луг, поле, бурьян |
| 5 | `lawn` | кошеный газон |

| 7 | `bare` | голый, вытоптанный грунт, стройплощадки |
| 8 | `sand` | песок (пляжи, намыв) |
| 9 | `gravel` | щебень, промплощадки, ж/д балласт |
| 10 | `water` | вода |
| 11 | `paved` | асфальт, плитка |
| 12 | `building` | крыши |

## Как устроено

**Признаки** (53 на пиксель; фильтры на 0.5 м, потом среднее 2×2): цвет Яндекса (RGB, яркость, ExG, VARI,
насыщенность, тон), сглаженные цвет и зелёность на 3 и 10 м, фактура (локальное СКО на 2/5/10 м, разность гауссов
на двух масштабах, когерентность структурного тензора — полосы грядок), тени и «высота через тень» (доля тени на
2/4/8 м по направлению тени, оно оценено по зданиям OSM: (−0.26, 0.97), т. е. тени на север), Esri — другая дата
съёмки (сглаженный цвет, фактура; разность зелёности сезонов), рельеф (уклон, локальный рельеф 40 м), доля частных
домов в окне 61 м. Esri совмещается с Яндексом фазовой корреляцией градиентов по каждому чанку (сдвиг 2–10 м).
Дистанции до зданий/дорог/воды OSM в признаки **не** входят: метки тоже из OSM, модель училась бы по ним.

**Слабые метки** — полигон OSM ∩ спектральное правило (только «чистые» пиксели): лес/парк/кладбище с зеленью и
фактурой → кроны; `natural=scrub` → заросли; `natural=grassland`/луга без фактуры и теней → луг; `landuse=grass`
у многоэтажек → газон; `allotments` без зелени → огород; стройки и грунтовые дороги → грунт; пляжи → песок; ж/д
пути и пром-территории (серое, ненасыщенное) → щебень; внутренности воды, проезжей части, парковок, зданий.

**Ручные метки** — `data/landcover/manual_labels.json`: ~45 прямоугольников по местам проверки (частный сектор,
Лесопарк, пустыри, пляж, промзона у Рязани-II, откос ж/д) + 374 точки (квадрат 3×3 м) из 20 листов
`trainsheets` (по 20 точек, стратифицированных по классу карты; размечены глазами по кропу Яндекса и Esri). Вес
ручной метки ×8. Точки обучения не ближе 40 м к точкам проверки.

**Модель** — LightGBM, 12 классов, 140 деревьев по 40 листьев, до 120 тыс. пикселей на класс, вес класса ∝ 1/√частота.
Предсказание по чанкам 1 км (поле 48 м); внутренности зданий и проезжей части OSM (> 2.5 м от края) не
предсказываются. ~25 мин на M4 (машина общая), обучение ~1 мин, признаки ~5 с на км².

**Чистка** (`post.py`): гаусс 1.2 м по вероятностям (аналог парных потенциалов CRF); «крыша» только ≤ 1 м от
здания OSM, «вода» ≤ 3 м от воды OSM; «асфальт» вдали от твёрдых покрытий OSM в частном секторе штрафуется (доля
мелких зданий в окне 61 м); тени Яндекса: неуверенный (< 0.6) или «тёмный» класс (асфальт/щебень/вода/крыша вдали от
OSM) пиксель в тени берёт класс ближайшего освещённого соседа; кольцо 3 м вокруг зданий (завал крыш, тень дома)
не бывает огородом/грунтом/щебнем; минимальные площади пятен (кроны 6 м², заросли 20 м², луг 40 м²…);
поверх — OSM: здания, вода (кроме нависающих крон), проезжая часть.

Площади по миру (7.25 × 7.5 км): кроны 11.0 км², заросли 3.6, луг 12.7, газон 1.3, огороды 0.3, грунт 1.1, песок
0.2, щебень 2.7, вода 3.2, асфальт 13.1, крыши 5.3.

## Точность

Проверочный набор — `data/landcover/validation_points.json`: 300 точек, случайных и стратифицированных по классу
карты (по 30 на класс земли, по 10 — асфальт/вода/крыши; только вне зданий и проезжей части OSM), класс поставлен
глазами по кропу 60×60 м Яндекса (+ Esri), 22 точки неопределимы (пропущены) → **278 точек**. Ни одна не лежит ближе
40 м к ручным меткам обучения. `uv run python build_landcover.py validate` → `data/processed/landcover/validation.json`.

| класс | n | полнота | точность |
|---|---|---|---|
| canopy (кроны) | 59 | 0.44 | 0.58 |
| thicket (заросли) | 18 | 0.44 | 0.28 |
| meadow (луг) | 65 | 0.52 | 0.85 |
| lawn (газон) | 14 | 0.36 | 0.21 |
| garden (огород) | 6 | 0.00 | 0.00 |
| bare (грунт) | 40 | 0.47 | 0.63 |
| sand (песок) | 19 | 0.90 | 0.65 |
| gravel (щебень) | 7 | 0.43 | 0.12 |
| water (вода) | 8 | 0.88 | 0.88 |
| paved (асфальт) | 18 | 0.44 | 0.26 |
| building (крыши вне OSM) | 24 | 0.21 | 0.56 |

- Доля верных по точкам — **0.475**; с весом по площади страт (оценка точности всей карты «открытой земли») —
  **0.56**; по укрупнённым группам (кроны+заросли / трава / грунт / вода / асфальт / крыши) — **0.665**.
- Главные путаницы: кроны ↔ заросли (граница размыта и при ручной разметке), луг ↔ газон и луг ↔ кроны (одиночные
  деревья на лугу), грунт ↔ песок, огород ↔ грунт/щебень (огородов в выборке 6 точек — оценка ненадёжна), асфальт ↔
  щебень. «Крыши» вне OSM (сараи, гаражи частного сектора) карта не знает: здания — только из OSM.
- Первая версия (только слабые метки OSM) давала 0.40; ручные точки подняли до 0.475. Дальше растёт ручной разметкой
  (`trainsheets` → допиши классы → `train predict post`), особенно для огородов, газонов и щебня.

Картинки проверки (Яндекс | наложение | классы): `data/processed/landcover/check/` — `lybed_south`,
`lybed_ravine`, `lesopark_edge`, `allotments`, `private_sector`, `oka_floodplain`, `industrial`,
`railway_verge`, `trubezh`, `beach`, `yards_center`, `scrub_floodplain` (+ `*_esri.png`).
Визуально: пойма Оки — сплошной луг с отдельными кустами; откос ж/д у Московского шоссе — заросли и бурьян;
овраг Лыбеди — кроны и заросли; частный сектор — кроны садов, огороды, газоны (огороды местами недобраны);
промзона у Рязани-II — щебень, бурьян, заросли вдоль путей; пляжи — песок.

## В мире

**Деревья** (`world/landcover_veg.py`, хуки в `world/props.py`):
- процедурное дерево (таблица `SCATTER`, деревья вдоль магистралей) остаётся, только если в радиусе 2 м (у улиц
  3 м) спутник видит кроны/заросли или класс неизвестен — на газонах, лугах, огородах, пустырях их больше нет;
- **деревья по кронам**: вершины крон — максимумы «расстояние до края массива крон + яркость освещённой макушки»,
  прорежены (не ближе 0.8 радиуса кроны большего соседа); добавляются там, где своих деревьев нет (дворы, овраги,
  обочины). Порода: хвойные → сосна; высокая тень (8–14 м) и крона > 3 м → тополь; светлая мелкая крона → берёза;
  иначе клён/липа/берёза. Масштаб — по радиусу кроны.
- Сборка 2026-10-14: всего деревьев 130 292 (было 123 511): процедурных ~89.5 тыс. (≈ 34 тыс. убрано с открытой
  земли), по кронам 40 752.

**Заросли** — клён ясенелистный (Acer negundo):
- точки класса `thicket` через 4 м с дрожанием; клумпа `thicket` (радиус 1.9–2.9 м, высота 3.2–8 м — тем выше и
  гуще, чем глубже в массиве); на краю массива ~12 % — отдельные `tree_negundo`. Не ставятся на дорогах, тротуарах,
  площадках, дорожках, ближе 2.2 м к зданиям и 2 м к щебню/асфальту/воде по карте (ж/д балласт). Внутри лесов и парков
  OSM — по краю (12 м) и каждая третья внутри; вне городской зоны — каждая вторая.
- Сборка: 97 433 клумпы, 4 046 кленов ясенелистных. `props/*.json` выросли до 37 МБ (несжатый JSON).
- Модель (`trees.ts`): многоствольная — 12 кривых наклонных стволиков (у отдельного дерева 4) с зеленовато-серой
  молодой корой, повислые боковые ветви, сложные перистые светлые листья (новая ячейка атласа 6). Сезоны общие с
  деревьями: осенью листва желтеет/краснеет и опадает, зимой — голые спутанные прутья под снегом. Вдали (> 80 м) —
  широкий импостер. Клумпы без теней (бюджет), ~2.1 тыс. треугольников на клумпу.
- Физика (`props.ts`, `breakables.ts`): цилиндр r = 0.78·радиуса — клумпы перекрываются, получается стена: игрок
  пешком и пешеходы (`queryObstacles`) не проходят. Машина продавливает тонкую клумпу с любой скорости (порог 4 км/ч,
  −9 км/ч на клумпу; клумпа наклоняется и приминается), густую (радиус ≥ 2.5 и высота ≥ 5.2 м) — только с разгона
  ≥ 55 км/ч и −45 км/ч. Проверка: на 16 км/ч в густую клумпу — стоп; на 70 км/ч сквозь массив у ж/д — пять клумп
  смято, скорость 63 → 50 → 43 → 45 км/ч, полный газ дальше еле тянет.

**Земля и трава** (`landcover.png`, 2 м, мода 2×2):
- рельеф (`materials.ts`): по 4 соседним ячейкам с дрожанием по шуму (без «лесенки» 2 м) — луг (пёстрый,
  соломенные пятна; осенью солома), газон (полосы покоса), огород (гряды ~1.1 м, направление своё на участок 24 м,
  часть грядок засажена летом), вытоптанный грунт, песок, щебень/асфальт вне OSM (дворовые проезды, промплощадки),
  подстилка под кронами и в зарослях (осенью — опавшая листва); на крутых склонах остаётся грунт;
- трава (`grass.ts`): по классу — плотность/высота/газон: луг — высокая трава с метёлками злаков (осенью соломенные),
  газон — коротко и густо, огород/грунт/песок/щебень — редко, под кронами — реже и ниже, в зарослях — бурьян;
  на площадках `area_grass` луг делает траву некошеной, грунт — вытоптанной. Снег прячет траву, как раньше.
- Нет файла `landcover.png` — игра работает как раньше (зелёность `veg.png`).

## Производительность

Откос ж/д у Московского шоссе, M4 (машина общая с другими агентами): +7 draw calls (пулы `thicket`/`tree_negundo`,
ближний и дальний LOD), +310 тыс. треугольников в кадре (99 клумп вблизи, 92 импостера), время рендера кадра в
пределах шума (1.4–1.6 мс CPU+finish). Первая версия с тенями клумп давала +1.9 млн треугольников — тени выключены,
ближний LOD сокращён до 80 м. Сборка трава окна — 0.2 мс (как раньше; маски тайлов пересчитываются один раз, когда
приходит карта покрова). Загрузка: `landcover.png` 1.4 МБ.

## Ограничения

- Точность карты по точкам ~0.48 (по группам ~0.67): заросли и кроны путаются, огороды недобраны, асфальт/щебень
  без OSM ненадёжны. Нужна дальнейшая ручная разметка.
- Хвойные не отделяются: порода сосна берётся только из OSM-лесов (процедурно) и класса `conifer` (пуст).
- В лесах OSM порода процедурная (сосна 42 %), хотя по снимку там часто густой лиственный молодняк (овраг Лыбеди).
- Осенний цвет зарослей — общая для лиственных смесь жёлто-оранжевого и красного (у клёна ясенелистного в жизни
  чисто жёлтый) — цвет осени не задаётся по породе.
- Примятая машиной клумпа остаётся примятой до перезагрузки тайла; коллайдер у неё убирается.
- Esri снят в другую дату и с завалом зданий: используется только сглаженно; тени Esri длиннее и мешают.

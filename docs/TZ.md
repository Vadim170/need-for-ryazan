# Need for Ryazan — ТЗ и инструментарий (v0.2)

## 0. Принятые решения

| Вопрос | Решение |
|---|---|
| Платформа | Mac (Apple Silicon). Игра в браузере, см. §3 |
| Аудитория | Только для себя, без публикации. Поэтому данные Яндекса и реальные марки машин использовать можно |
| Бюджет | Только бесплатные инструменты и ассеты |
| Управление | Аркада в духе NFS: дрифт по нажатию, assists, нитро |
| Звук | Отдельный приоритет: «бархатный» рёв двигателя (V8-характер) |
| Рельеф | Реальные перепады высот, а не «примерно». Только из открытых карт высот: своих замеров не будет |
| Первая машина | Lada Largus, детализированная, **тюнингованная** (обвес, занижение, диски, приятный «спортивный» звук) |

## 1. Цель

Открытый мир в духе Need for Speed: центр Рязани в реальном масштабе (1 юнит = 1 м, реальная геопривязка), «живой» город с трафиком и пешеходами, смена дня и ночи. Миссий пока нет: игрок появляется на случайной дороге и свободно ездит.

Главные критерии качества (по приоритету):
1. **Машина ощущается и звучит круто**: отзывчивое аркадное управление, вес, занос, сочный звук, камера, ощущение скорости.
2. **Город узнаётся**: точная геометрия улиц, полос, перекрёстков, **реальный рельеф**, узнаваемые ориентиры.
3. **Город живёт**: трафик по полосам и светофорам, пешеходы, общественный транспорт, день и ночь.

## 3. Технологический стек

### Решение: браузерная игра (TypeScript + Three.js)

| Слой | Технология | Почему |
|---|---|---|
| Язык / сборка | TypeScript + Vite | Быстрый hot-reload, всё в коде |
| Рендер | **Three.js** (WebGPURenderer, фолбэк WebGL2) | Самый большой экосистемный набор: PBR, тени (CSM), постобработка, инстансинг, LOD, KTX2/Draco/Meshopt |
| Физика | **Rapier** (WASM) | Быстрая, детерминированная. Машину делаем своей аркадной моделью на raycast-подвеске |
| Звук | **Web Audio API** + AudioWorklet | Кроссфейд сэмплов по RPM и нагрузке, свои эффекты |
| Мир | Свой стриминг тайлами (например, 250×250 м): glTF-чанки, сгенерированные пайплайном | Весь город сразу в память не грузится |
| Трафик и пешеходы | Своя симуляция по графу полос (TS, позже Web Worker), машины через InstancedMesh | Тысячи агентов дёшево |

Почему веб, а не Unreal или Godot:
- Unreal Engine 5 на Mac работает, но разработка в нём завязана на GUI-редактор и бинарные Blueprint-ассеты. Писать и проверять его код мне неудобно, а на Mac он к тому же тяжёлый.
- В вебе весь проект — это текст и код. Я могу сам запускать игру в Chrome, делать скриншоты и проверять результат. Итерации самые быстрые, всё бесплатно.
- Цена: потолок графики ниже, чем у UE5, и производительность придётся вылизывать (инстансинг, LOD, стриминг, бейкинг света).
- **Запасной вариант**, если упрёмся в производительность: **Godot 4** (бесплатный, нативный Metal на Mac, сцены тоже текстовые). Пайплайн данных (glTF-чанки) переносится без изменений.

## 4. Конвейер данных (pipeline)

```
 OSM (дороги, полосы, здания, POI)   ─┐
 Рельеф (DEM + свои замеры, §5.2)     ├─► [Python: GDAL, shapely, pyproj, osmium] ─► GeoPackage в единой СК
 Яндекс (спутник, панорамы, §5.6)    ─┤                │
 Ручные правки (JOSM, оверрайды)     ─┘                ├─► Дороги ─► SUMO netconvert ─► OpenDRIVE (.xodr) / граф полос
                                                       │                ├─► меши дорог, разметка, бордюры ─► glTF
                                                       │                └─► граф полос ─► JSON для трафика
                                                       ├─► Рельеф ─► heightmap-тайлы + «вжатие» дорог
                                                       ├─► Здания ─► процедурная генерация по типам (Python / Blender GN) ─► glTF
                                                       └─► Пропсы (фонари, светофоры, деревья, знаки) ─► точки для инстансинга
 Hero-объекты (Кремль и т.п.) ─► Blender / фотограмметрия ─► glTF по координатам
                                                       ▼
                                      Тайлы мира 250×250 м (glTF + JSON) ─► игра
```

Принципы:
- **Единая система координат**: локальная Transverse Mercator с центром в Кремле. Все слои переводим в неё до генерации.
- **Воспроизводимость**: пайплайн — это скрипты в репозитории, мир пересобирается одной командой. Ручные правки живут в OSM (JOSM) или в слоях-оверрайдах (GeoJSON), а не в сгенерированных файлах.
- **Уровни детализации**: hero-здания делаем вручную, типовые процедурно из наборов модулей, фон упрощённой экструзией.

## 5. Источники данных

### 5.1 Дороги и полосы

| Источник | Что даёт | Как используем |
|---|---|---|
| **OpenStreetMap** | Оси дорог, `lanes`, `turn:lanes`, `oneway`, `maxspeed`, `width`, светофоры, переходы, `lit`, остановки, маршруты троллейбусов/автобусов, мосты (`bridge`, `layer`) | **Основа геометрии** |
| **Яндекс-спутник** (тайлы) | Видно разметку, островки, ширины | Подложка в JOSM/QGIS для ручной доразметки полос |
| **Яндекс-панорамы** | Знаки, полосы, разметка с уровня дороги | Сверка спорных перекрёстков |
| Mapillary | Уличные фото, распознанные знаки | Дополнительно, если есть покрытие |

Готового инструмента, который выгружает из Яндекса **граф полос**, на GitHub не нашлось (§5.6). Поэтому полосы берём из OSM и доразмечаем в JOSM, подложив снизу Яндекс-спутник и панорамы.

### 5.2 Рельеф: реальные перепады высот

Требование: склоны должны быть как в жизни. Спуски к Трубежу и Оке у Кремля, Лыбедский бульвар, подъёмы на Первомайском, мосты и путепроводы.

| Источник | Точность | Роль |
|---|---|---|
| **FABDEM** (Copernicus без зданий и леса) | 30 м, вертикаль ~2–5 м | Базовая поверхность «голой земли» (некоммерческая лицензия, нам подходит) |
| Copernicus DEM GLO-30 | 30 м | Запасной / для сравнения |
| Советские топокарты 1:25 000 / 1:10 000 (сканы в открытом доступе) и старые топопланы | Горизонтали через 2.5–5 м | Склоны вне дорог (кремлёвский холм, поймы) |
| OSM `bridge` / `tunnel` / `layer` / `incline` / `steps` | — | Структура: где дорога над дорогой, где лестницы |
| Google Photorealistic 3D Tiles | ~1 м | **Покрытие Рязани не подтверждено.** Бесплатная квота требует привязки карты к Google Cloud. Проверить на этапе 0 |

Проверено: **в метаданных Яндекс-панорам абсолютной высоты нет** (у точек z = 0), так что этот путь закрыт.

Алгоритм: FABDEM → сглаживание → выравнивание коридоров дорог по OSM (плавные продольные профили, мосты по `bridge`/`layer`) → ручная доводка склонов по топокартам. Своих замеров нет (решение пользователя). Детали по итогам аудита рельефа: `docs/stage0/terrain-audit.md`.

### 5.3 Здания

| Источник | Что даёт |
|---|---|
| OSM `building`, `building:levels`, `height`, `roof:shape`, `building:part` | Футпринты (~8.2k в зоне) и частично этажность. **Покрытие этажностью нужно измерить** (этап 0) |
| Реестр ЖКХ («Реформа ЖКХ», ГИС ЖКХ) | Год постройки, этажность, иногда серия дома по адресу. Сопоставляем с OSM по адресу и **автоматически назначаем типовую серию** (1-464, 1-447, II-49, П-44 и т.д.) |

Подход: **библиотека типовых серий** (панельки и кирпичные хрущёвки/брежневки, сталинки, частный сектор, ТЦ, гаражи), из модулей которой генератор собирает дом по футпринту и этажности. Это главный рычаг, чтобы ~8000 зданий выглядели «по-рязански».

**Чего нет:** готовых инструментов для **векторных тайлов Яндекса** (формат `vmap2`, protobuf). Именно там могут лежать высоты зданий, 3D-модели ориентиров и детальная геометрия. ## 6. Машина: аркадное управление и звук

### 6.1 Управление (NFS-стиль)
- Своя модель поверх Rapier: raycast-подвеска на 4 колеса, упрощённая модель шин с кривыми сцепления.
- **Assists:** стабилизация на прямой, авто-контрруль, ограничение угла заноса.
- **Дрифт:** вход по тормозу или ручнику на скорости, удержание газом, выход без «пилы».
- Нитро, мягкое сглаживание коллизий с трафиком (не «залипать» в стенах).
- **Ощущение скорости:** FOV от скорости, лёгкая тряска камеры, motion blur, «летящие» частицы, наклон кузова, отклик руля.
- Управление с клавиатуры и геймпада (Gamepad API).
- Тюнинг через параметры в JSON + debug-панель (lil-gui) прямо в игре.

### 6.2 Звук двигателя: «бархатный рёв»
Техника, как в больших гонках: **слои сэмплов по RPM × нагрузке с кроссфейдом**.
- Набор зацикленных записей: on-load (газ) и off-load (сброс), каждая на 6–10 точках оборотов (≈1000…7000 rpm). Между точками кроссфейд и небольшой pitch-shift.
- Отдельные слои: впуск (салон), выхлоп (снаружи), **хлопки и прострелы на сбросе газа**, переключение передач, визг шин (по скольжению), турбо (опционально).
- Эффекты: низкочастотный «бархат» (EQ, лёгкая сатурация), **отражения от зданий** (convolution reverb, сила зависит от плотности застройки рядом), эхо под мостами, допплер для встречного трафика.

Бесплатные источники звука:
| Источник | Что |
|---|---|
| freesound.org (CC0 / CC BY) | Записи V8 (Mustang, AMG, Camaro): прогазовки, проезды, холостой ход. Нарезаем в RPM-лупы |
| [DasEtwas/enginesound](https://github.com/DasEtwas/enginesound) (385★, MIT, Rust, работает на Mac) | Процедурный генератор: выдаёт WAV по параметрам двигателя. Дополняем или заменяем записи |
| [ange-yaghi/engine-sim](https://github.com/ange-yaghi/engine-sim) (9.6k★, MIT) | Самый реалистичный симулятор, **но только Windows**. Можно один раз записать лупы на чужом ПК или в виртуалке |
| Звуки трафика, города, птиц, дождя | freesound.org, Sonniss GDC bundles (бесплатные ежегодные паки) |

## 8. Этапы

### Этап 0. Аудит данных и скелет (1–2 нед)
- Выкачать OSM-экстракт, измерить покрытие: этажность, `lanes`, `turn:lanes`, `width`, светофоры, переходы, фонари, деревья.
- Скачать FABDEM и Copernicus и сравнить с известными перепадами (кремлёвский холм).
- Проверить покрытие Google 3D Tiles и Mapillary по Рязани.
- Список hero-объектов и поиск готовых моделей.
- Скелет проекта: Vite + Three.js + Rapier, пустая сцена с машиной на плоскости.
- **Результат:** отчёт «что есть / чего не хватает» с цифрами.

### Этап 1. Серый бокс + машина (2–4 нед)
- Рельеф из DEM, дороги из OSM через netconvert, здания экструзией, стриминг тайлами.
- Аркадная машина, спавн на случайной дороге.
- **Результат:** можно проехать от площади Победы до поста ДПС по реальной сетке улиц с реальным (пока грубым) рельефом.

### Этап 2. Машина: управление и звук (параллельно, итеративно)
- Аркадная модель, дрифт, нитро, камера, эффекты скорости.
- Звуковой движок RPM × нагрузка, первая «бархатная» машина.
- Тестовый полигон + эталонный маршрут по городу.

### Этап 3. Точный рельеф и дороги (4–8 нед)
- Доводка рельефа: коридоры дорог, мосты, склоны по топокартам.
- Доразметка полос в OSM (JOSM + Яндекс-спутник и панорамы).
- Разметка по ГОСТ, бордюры, тротуары, островки, мосты, троллейбусные провода, светофоры, знаки, фонари.

### Этап 4. Живой город (4–8 нед)
- Трафик по графу полос: светофорные фазы, перестроения, реакция на игрока.
- Пешеходы по тротуарам и переходам.
- Автобусы и троллейбусы по реальным маршрутам из OSM (опционально).

### Этап 5. День и ночь (2–3 нед)
- Солнце по реальной широте и дате, небо, ночное освещение (фонари, окна, фары, вывески; запечённые эмиссивные карты вместо тысяч динамических источников), плотность трафика по времени суток.

### Этап 6. Здания и hero-объекты (долго, итеративно)
- Библиотека типовых серий → процедурные фасады.
- Hero-объекты по одному. Растительность, дворы, заборы, гаражи, мелочи.

### Этап 7. Оптимизация
- LOD, инстансинг, сжатие (Meshopt, KTX2), бюджеты кадра на целевом Mac.

## 9. Чего не хватает (риски и пробелы)

| Пробел | Критичность | Как закрываем |
|---|---|---|
| Детальные полосы в OSM (покрытие неизвестно) | Высокая | Аудит → ручная доразметка в JOSM по Яндексу |
| Точный рельеф (DEM 30 м грубый) | Высокая | FABDEM + выравнивание по дорогам + топокарты |
| Этажность зданий | Средняя | OSM + реестр ЖКХ + дефолты по типу |
| Фасады ~8000 зданий | Высокая (объём) | Типовые серии + процедурка |
| Hero-модели | Высокая для узнаваемости | Готовые → фотограмметрия → Blender |
| Производительность веба на большом городе | Средняя | Стриминг, инстансинг, LOD; запасной путь Godot 4 |
| Качественные бесплатные модели машин | Средняя | Sketchfab CC + ручное упрощение |
| Векторные данные Яндекса | Неизвестно | Опциональный реверс после этапа 0 |
